# Stage10 经验结算（生命层次 + 习得）

只输出一个合法 JSON 对象，不要 Markdown、解释或正文。

本阶段在 Stage4–8 **之后串行**执行，结算两类经验：

1. `gains`：生命层次能量经验（击杀/吸收）
2. `learnedGains`：知识 / 技能 / 职业经验（正文中的练习与使用）

## A. 生命层次经验 gains（强制）

- **经验** = 能量积累。
- 合法来源只有两类：
  1. `kill`：明确击杀生命体并吸收其生命能量
  2. `absorb`：明确吸收他人/他物的能力、能量、精魄等
- **升级** = 生命层次提升（系统自动处理，AI 不要直接改 level）。
- 禁止：日常行动、社交、单纯学习/锻炼、单纯受伤、氛围描写、未确认击杀/吸收 → 不要写入 `gains`。

### 经验档位（硬约束）

按「被击杀/被吸收来源」的大概生命层次 `sourceLevel`（1-100）落入固定档位，`expGain` 必须落在该档内：

| 来源层次 | 允许经验 |
| --- | --- |
| 1-10 | 1-10 |
| 11-20 | 11-20 |
| 21-30 | 21-30 |
| 31-40 | 31-40 |
| 41-50 | 41-50 |
| 51-60 | 51-60 |
| 61-70 | 61-70 |
| 71-80 | 71-80 |
| 81-90 | 81-90 |
| 91-100 | 91-100 |

规则：

1. `sourceLevel` 取正文可推定的大致等级；不确定时保守取偏低档。
2. 同档内：越接近档顶、对抗越激烈、能量越完整，`expGain` 可取较高；残缺吸收、轻易碾压取较低。
3. `quality` 只能是：`low` / `normal` / `high` / `peak`。质量只影响档内高低，**不能越出档位**。
4. 系统会再次钳制 `expGain`；越档无效。
5. 同一来源本回合只记一条；多条不同来源可并列，最多 8 条。

## B. 知识 / 技能 / 职业经验 learnedGains（强制）

这是知识/技能/职业经验的**唯一来源**。系统不会再因回合自动给习得经验。

规则：

1. 仅当正文明确出现练习、使用、实操、调试、授课、考核、实战运用某项**已有**知识/技能/职业时才给。
2. `learnedType`：`knowledge` | `skill` | `profession`（或中文 `知识` | `技能` | `职业`）。
3. `name` 必须与提示中「已有习得列表」名称精确匹配；禁止新建条目。
4. `expGain`：1–80 正整数。轻描淡写取低，持续练习/关键实操取高。
5. 已满级（lv7）或不存在的名称 → 不要输出。
6. 同一条目本回合最多一条；总数最多 12 条。
7. 无相关事实 → `learnedGains: []`。

## 结算对象

- `subject`：获得经验的人。
- 玩家本人用 `{"id":"player-self","name":"玩家名"}`；角色用真实 id/姓名。
- 只能结算本回合参与者或正文明确执行者。

## 输出合约

```json
{
  "gains": [
    {
      "subject": { "id": "player-self", "name": "玩家名" },
      "sourceType": "kill",
      "sourceName": "来源名",
      "sourceLevel": 12,
      "quality": "normal",
      "expGain": 14,
      "evidence": "正文明确击杀并吸收能量的短证据"
    }
  ],
  "learnedGains": [
    {
      "subject": { "id": "player-self", "name": "玩家名" },
      "learnedType": "skill",
      "name": "编程与软件开发",
      "expGain": 12,
      "evidence": "正文明确练习或使用该技能的短证据"
    }
  ],
  "done": true
}
```

无任何事实：

```json
{ "gains": [], "learnedGains": [], "done": true }
```
