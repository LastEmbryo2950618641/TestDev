# Stage9-1 势力完整创建

你负责根据本轮完整上下文创建全部尚未入库的势力，并一次补全每个势力的完整信息。

只输出一个合法 JSON 数组。首字符必须是 `[`，末字符必须是 `]`。不要输出 Markdown、解释、正文或 JSON 数组之外的任何文字。

## 创建规则

- 重新检查本轮完整上下文。只要识别到尚未入库的势力线索，就必须创建；即使 Stage1 候选为空也必须复查。
- Stage1 标记为待创建的势力必须逐项处理。候选称呼只是线索，不是最终名称。
- 必须根据上下文合理推演并一次补全每个势力的完整信息，不能返回空壳、临时名称或仅有基础字段的记录。
- Stage1 候选已有 `id` 时必须原样沿用；复查中新发现且没有 ID 的势力才生成稳定唯一 ID。
- 同一响应一次返回全部需要创建的势力。没有需要创建的势力时返回 `[]`。
- `reason` 可省略；代码会补充创建原因。
- 禁止使用 `ops`、`done`、`method`、`params` 或任何操作外壳。
- JSON 容器最多四层。复杂列表必须使用下面规定的紧凑字符串，不得在列表中继续嵌套对象。
- 浅层传输结构不等于草稿；不要为了减少字段而省略可由上下文稳定推演的信息。

EXAMPLE JSON OUTPUT:

```json
[
  {
    "candidate": "Stage1 原候选称呼",
    "id": "沿用的候选 ID 或新生成 ID",
    "name": "结合上下文补全的最终势力名",
    "type": "组织类型",
    "kind": "可选分类",
    "class": "classification",
    "world": "所属世界",
    "parent_id": null,
    "parent_name": null,
    "level": "层级",
    "location": "地点",
    "domain": "领域",
    "scale": "规模",
    "stance": "立场",
    "influence": 30,
    "desc": "完整简介",
    "structure": ["部门名|职位A,职位B"],
    "rules": ["规则"],
    "resources": ["资源"],
    "relations": ["对象|关系类型|对方视角（可省略）"],
    "ideo": { "core": "核心理念", "base": "理念基础", "desc": "理念说明", "legit": 60 },
    "econ": { "income": "收入结构", "orgs": ["机构名|职责说明"] },
    "pol": { "regime": "治理结构" },
    "mil": { "posture": "安全或军事姿态", "forces": ["编组名|组成A,组成B"] },
    "dip": { "allies": ["对象|关系说明|对方视角"] },
    "ter": { "capital": "核心地点", "regions": ["区域名|中心|面积|控制程度|人口|说明|驻防"] },
    "reason": "可选创建依据"
  }
]
```

紧凑列表格式：

- `structure`：`部门名|职位A,职位B`。
- `relations`：`对象|关系类型|对方视角`，第三段可省略。
- 面板机构列表：`机构名|职责说明`。
- `mil.forces`：`编组名|组成A,组成B`。
- `dip.allies` / `dip.rivals`：`对象|关系说明|对方视角`。
- `ter.regions`：`区域名|中心|面积|控制程度|人口|说明|驻防`。
- 面板 key 只使用 `ideo`、`econ`、`pol`、`mil`、`dip`、`ter`，直接放在势力对象顶层；禁止再包 `panels`。
