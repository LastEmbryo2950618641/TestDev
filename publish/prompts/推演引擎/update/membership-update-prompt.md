# Stage4 人事归属更新

正文或已载入资料中出现、有事实依据的组织身份变化时，使用 `membership` 结算写入 `profile.memberships`。仅处理本轮新确认或发生变化的稳定事实，不扫描或补写旧存档中本轮没有变化的归属。不要把门槛收得过死：入职、任职、调岗、离职、升学、转学、入学、退学、入籍/登记公民、社团正式成员变动等，只要有稳定事实依据均可写。

## 1. 定义（含义）

- **人事归属**：角色在可指认组织实体中的正式或准正式身份——“我在这个组织里担任什么”。
- 与 **社群角色** 的区别：社群角色强调软性圈子里的社会角色（家庭角色、社区居民、朋友圈位置等）；人事归属强调组织编制、学籍、职级、成员身份等可核对关系。
- 边界模糊时选更贴近的一类；**禁止因过严分类把本有事实依据的身份判成“都不是”**。纯社群角色变化请写「角色卡 → 社群角色」，不要硬塞本类型。

## 2. 构成要素

每条人事归属必须按 `完整组织名 / 具体职位、学籍或成员身份` 完整表达，并具备：

- `orgName` / `orgId`：组织名；能对应势力系统已有 stub 时优先带 `orgId`
- `title`：职位 / 学籍 / 成员身份
- `department`：部门；未明则空字符串且 `departmentFog: true`
- `state`：fog | sketch | established（按确认程度）
- 原因：点明正文或资料中的事实依据

## 3. 归类完备性（尽可能全）

- 本轮正文/资料新确认组织身份时，有事实或背景依据时必须完整补全并写入本类型（追加或替换）；完全没有事实或背景依据时才允许不写。
- 求全优先于过严过滤；不要因“只是提及”“尚未办手续描写很细”等理由丢弃已确认的编制事实。
- 明确事实优先；当本轮已确认地区、教育阶段、职业领域或组织类型但缺少次要细节时，应结合世界观、年代、地区和人物经历作最小充分推演，补齐完整组织名和具体职位、年级或成员身份。不得生成与背景矛盾的组织或无关扩张。
- 禁止用“某公司”“未知学校”“相关机构”“普通职员”“初中生”“成员”等模糊占位规避可推演的信息；不要写无主体空壳（如单独“现实社会/成年人”且无具体组织名）。
- 具体国家下的公民/国民有依据时可写；抽象空壳“居民”无组织名时不要单独写本类型（可改社群角色）。
- 输出前逐项自检本轮变化：组织名、职位/学籍/成员身份以及可推演部门是否完整；本轮未变化的旧归属不要重写。

## 4. 分工

- 组织树职位占坑 → 可同时写 `faction-structure`
- 角色主观组织归属 → 本类型写 `profile.memberships`
- 两边应尽量一致
