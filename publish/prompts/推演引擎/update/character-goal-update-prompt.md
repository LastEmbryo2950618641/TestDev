# Stage4 长期目标更新

确认玩家或角色的长期目标系统发生稳定变化时，使用“长期目标”结算类型输出 JSON。

## 字段

- 目标内容
  - 短期目标 / 中期目标 / 长期目标（JSON 键：`short` / `medium` / `long`）
  - 每项可含：`content`（目标内容）、`deadline`（完成期限 YYYY-MM-DD）、`progress`（0-100）、`detail`（进度描述）
- 阶段成果：`achievement` 或 `achievements[]`（追加已完成成果）

## 档位判定（短 / 中 / 长）

当玩家或正文提出新目标、但未点名「短期/中期/长期」时，**必须根据任务难易与预期耗时自行归档**：

| 档位 | 典型时长 | 判定提示 |
| --- | --- | --- |
| 短期 `short` | 数天～数周；「近期」「这周」「先把…做完」 | 单次冲刺、可较快闭环的具体任务 |
| 中期 `medium` | 数月；「几个月内」「这学期」「先站稳…」 | 需要阶段积累、多步推进才能兑现 |
| 长期 `long` | 数年或人生方向；「以后要…」「最终成为…」 | 方向性追求，短期内不可能闭环 |

若玩家**明确**说了「短期目标 / 中期目标 / 长期目标 / 近期完成 / 几个月内达成」等，以玩家指定档位为准；仅在未指定时用上表推断。

## 规则

1. 只更新本回合 participants 中的角色/玩家；同一人可合并短中长期与成果到同一条。
2. 只写正文明确或强确认的目标内容/期限/进度变化；弱推测不写。
3. 进度变化必须有正文事实支撑（完成步骤、达成节点、受阻等）；`progress` 为整数 0–100。
4. 阶段成果只追加已完成节点，不要把仍在进行的目标写成成果。
5. 未变化的期限/进度字段可省略；不要清空未提及字段。
6. 当前即时「下一步行动」仍写基础结算的「当前目标」；本类型管短/中/长期目标系统。

### A. 任一档进度达到 100%（完成）——必须换新目标

当某档（short / medium / long）在本回合被确认完成（`progress` 写为 100，或正文明确该档目标已达成）时，**同一条结算必须同时**：

1. 将该完成事实写入 `achievement` / `achievements`（阶段成果）；
2. **基于当前上下文（处境、关系、职业、刚完成的成果、玩家意向）生成同档下一条新目标**，写入该档的新 `content`；
3. 为新目标给出合理的 `deadline`（可估）、将 `progress` **重置为较低起点**（通常 0～20，视是否已有铺垫），并写 `detail` 说明为何是这个起点。

禁止：完成后面该档仍留着旧 `content`、或只写 100% 不换新目标。

### B. 玩家明确改目标 / 加目标——与未完成进度融合（强制）

**触发前提（必须同时满足）：** 玩家输入或正文对目标表达**特别明确**，例如点名短期/中期/长期，或含「希望几个月内达成」「近期完成」「作为短期目标」「中期要…」「长期想…」等清晰意图。模糊愿望、随口一提、纯情绪发泄 → **不**触发融合改写。

当触发且该档**旧目标尚未完成**（progress < 100）时：

1. **不得直接丢弃**旧目标进度与已铺垫事实；
2. 新 `content` 必须是「旧目标未完部分 + 新明确目标」的**综合表述**（可并存、可分主次，但两边都要落进内容）；
3. `progress` 按综合后的整体完成度**重估**，通常应**适当降低**（因为总任务变难/变宽），并在 `detail` 写清：旧进度保留了什么、新要求加了什么、为何调到该进度；
4. `deadline` 按综合目标重新估计；若玩家给了时限，优先贴合玩家时限。

示例：旧短期「交一个女朋友」，已与某女生很暧昧但未成男女朋友；玩家明确改为短期「考上清华」→ 新短期应综合为同时推进「拿下这段关系成为男女朋友」与「冲刺考上清华」，进度相对纯暧昧阶段可下调，并说明依据。

若旧目标已 100% 完成，则走规则 A：先记成果，再按新意图与上下文生成同档全新目标（不必再融合已完成的旧 content）。

### C. 仅进度推进（未完成、未改目标）

正文推进了原目标但未完成、玩家也未明确改目标：只更新 `progress` / `detail`（及必要时微调 `deadline`），不要无故改写 `content`。

## JSON 示例

### 示例 1：完成短期并换新短期

```json
{
  "subject": "刘悠",
  "short": {
    "content": "把汇报后的整改清单在两周内落地，并约开一次三人复盘",
    "deadline": "2026-08-14",
    "progress": 10,
    "detail": "汇报已完成；新目标刚起步，仅理清整改项"
  },
  "achievement": "完成本周项目汇报并获得主管口头肯定",
  "reason": "正文明确汇报结束；按完成规则生成下一条短期目标"
}
```

### 示例 2：玩家明确改短期，与未完成进度融合

```json
{
  "subject": "刘悠",
  "short": {
    "content": "在维持与对方暧昧推进并尽快确认男女朋友关系的同时，启动考清华所需的复习与报名准备",
    "deadline": "2026-09-30",
    "progress": 25,
    "detail": "感情线已有暧昧铺垫故保留部分进度；叠加考学后整体难度上升，进度下调并重估期限"
  },
  "reason": "玩家明确提出近期/短期要考上清华，且旧短期交女友尚未完成，按融合规则改写"
}
```
