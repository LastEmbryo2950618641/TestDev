# Stage4 性历史更新

确认玩家或角色的性经历身份状态发生稳定变化，或需把 `未知` 固化为明确状态时，使用“性历史”结算类型输出中文 K:V 更新。

- 绑定卡片：角色卡；玩家本人绑定玩家卡。
- 只处理成人虚构身份的抽象元数据，不输出过程、姿势、器官互动或感官细节。
- 当前状态字段：性经历身份当前状态；允许值含 `未知` / `处女` / `处男` / `非处女` / `非处男`。
- 经历人数字段：稳定确认的经历人数；**由系统根据经历人列表自动计算，AI 不要单独写人数**。
- 经历人列表字段：稳定确认的经历人名字列表（可 append 去重）。
- 经历人数只在稳定事实确认发生过“阴部插入”时计入；其他亲密经历、接吻、口部、胸部、肛部、皮肤接触等均不增加经历人数。
- 操作：替换、追加或增减。
- 每条更新只描述一个稳定事实变化。
- AI 面向格式：更新N：性历史，状态转移，性对象，原因与证据。
- 必须在事实确认发生过“阴部插入”时，才记录经历人数或经历人列表变化。
- 写入经历对象时只追加姓名（或可识别对象）；系统会自动把经历人数同步为去重后的名单长度。禁止单独 set 经历人数。
- 触发原因：写明导致状态变化的稳定事实来源，保持中性概述。
- 证据：写阶段正文或已载入资料中的依据，禁止露骨描述。
- 若原本无“性技”技能，则额外新增等级为 1 的“性技”技能，并新增“性知识”知识条目；若已存在则不重复新增。

## 未知 → 处女/处男/非处女/非处男（强制）

当前为 `未知`（或尚未初始化）时，**禁止**无依据写成处女。按以下优先级判定 `transition`：

1. **正文明确事实**（破处、自述初夜、档案已婚/已育等）→ 直接转移。
2. **身份推定**（无相反特殊背景）：妻子/丈夫/配偶/已婚/丧偶/再婚/已育 → `未知→非处女` 或 `未知→非处男`；对象可写配偶名或“配偶”。
3. **世界观默认**（身份不足、无特殊个人说明）：
   - 守贞/贞洁被强调，或以失贞为耻；古老部落等以童贞为规范 → 无特殊背景的少女/少年默认 `未知→处女` / `未知→处男`。
   - 童贞可耻或性开放为常态且角色已成年融入 → 可默认 `未知→非处女` / `未知→非处男`。
   - 现代都市未婚且无插入证据 → 可继续保持未知，本类型输出空，不要硬填。
4. **本轮确认阴部插入**：若此前未知或处女/处男 → 转移为非处女/非处男，并记对象与证据；可同轮先写“此前为处女/处男”的确认，再写转入非处（两条各写一个稳定事实）。

`transition` 建议写成可读短句，如 `未知→非处女`、`处女→非处女`；`evidence` 写身份或正文依据（如“角色卡身份为妻子”）。

若变化能归入角色卡或词条字段，优先使用对应专用类型；本类型只负责性历史抽象稳定事实。
