# Stage4 角色卡更新

确认玩家或已有完整角色卡资料、身份、职业、技能、外貌、性格、人际关系等稳定变化时，使用“角色卡”结算类型输出中文 K:V 更新。

- 绑定卡片：已有完整角色卡；玩家本人绑定玩家卡。
- 字段：身份、职业、技能、外貌、性格、喜好、人物说明、社群角色、人事归属、证书、称号、人际关系、当前状态等中文字段。
- 操作：替换或增加。
- 只有稳定事实变化才写；临时情绪不要写入角色卡。
- 新登场且仅有介绍卡/空壳 stub 的人物或存在，不在这里生成完整角色卡；只通过 Stage4 的 appearedCharacters 补介绍卡候选，完整角色卡仅玩家手动升格。
- **禁止修改本质偏好五层**：价值立场偏好、决策风格偏好、人生六维偏好、底线锚点偏好、心理偏好为永久固化字段，不得通过角色卡结算更新。

若变化能归入角色卡字段，优先使用角色卡类型。组织编制类变动（入职/调岗/学籍等）可写「人事归属」字段，资格认证类写「证书」，社会认可名号写「称号」；以事实为准，不要因类型犹豫而漏写。

## 社群角色 / 人事归属 / 证书 / 称号（字段说明）

### 1. 定义（含义）

- **社群角色**：角色在软性社会关系网中的位置——“我在这个圈子里是谁”（家庭、社区、朋友圈、兴趣小组、临时群体等）。
- **人事归属**：角色在可指认组织实体中的正式或准正式身份——“我在这个组织里担任什么”（学校、公司、机关、国家公民、正式家庭组织等）。
- **证书**：某个组织或势力对人物在某个领域的资格认证——“谁证明我具备什么资格/等级”。
- **称号**：社会群体对人物成就、名望或过往功绩的认可——“某个群体怎样称呼/认可我”。

先按含义判断，不要因措辞不够“硬/官方”就整条丢掉；边界模糊选更贴近的一类，**禁止判成全部都不是**。组织职位写人事归属，资格认证写证书，社会认可名号写称号，软性圈层位置写社群角色。

### 2. 构成要素

- **社群角色**：社群/圈子名 + 其中角色。
- **人事归属**：组织名 + 职位/学籍/成员身份（+ 部门；未知可省略并标明部门未明）。
- **证书**：认证组织/势力 + 领域 + 资格认证等级，展示为 `<组织>/<领域>/<资格认证等级>`。
- **称号**：认可社会群体 + 领域 + 称号名，展示为 `<社会某团体>/<领域>/<称号名>`。

### 3. 归类完备性（尽可能全）

- 正文或资料中**已经出现**、有事实依据、**非胡编**的稳定身份、归属、资格认证、社会称号，**必须**归入社群角色、人事归属、证书、称号四者之一（或要素不同时合理多边各写）。
- 求全优先于过严过滤；弱氛围猜测仍不写，但已确认事实不得因分类犹豫而省略。
- 证书和称号不得重复；同一 `<组织>/<领域>/<资格认证等级>` 或同一 `<社会某团体>/<领域>/<称号名>` 只写一次。
