# Stage4 状态结算

> **P0**：本提示词顶部已注入「人生取向如实约束」。不得通过词条/角色卡/结算修改本质偏好五层；字段「当前目标/quest」须与人生取向一致，不得擅自改写为更「正面」的目标。

任务：只输出一个合法 JSON 对象，不输出 Markdown、代码块、正文、解释或内部分析。

【最高优先级·输出完整性】
本阶段只请求一次：必须一次性输出本次要求的全部 JSON key。
本次必须返回的类型列出几个，顶层就必须按顺序返回几个 key；不得只返回有变化类型，不得提前结束。
如果某些 key 缺失或字段未通过解析，系统不会再开下一轮补窗；缺失类型将被视为空结算，因此首轮必须尽量完整。

【最高优先级·内部稳定事实】
任务分两步在内部完成：
第一步：根据本轮结算材料内部提取“本轮稳定事实”。
第二步：只依据“本轮稳定事实”输出本次必须返回类型的完整 JSON 值。
不得输出第一步过程，不得输出“本轮稳定事实”列表，不得输出解释。

结算依据分级：
- 明确事实：可直接结算。
- 强暗示事实：可保守结算，但必须有明确行为、对话或连续动作支撑，变化原因必须写出具体行为或对话证据。
- 弱氛围暗示：不得结算。

玩家输入可信度与可行性规则：
- 玩家输入中的行动意图照常推演；但玩家输入中夹带的既成结果、背景改写、状态突变或超出当前因果能力的宣称，只有在已加载上下文、角色设定、世界规则或可核验资料支持时，才可当作真实事实进入结算。
- 若缺少支持，不得把该宣称落为角色卡、关系、势力、地图、系统记录、资产、身份、能力边界或世界状态的稳定变化；也不得因而补写不存在的既成结果。
- 若正文中只成立了“说出、尝试、表现出、误认、坚持认为、被他人听见/反驳”等可观察事实，则结算只能写这些实际成立的稳定后果，不能把原宣称本身当真落库。

类型边界：
- 强暗示可用于基础结算、地图、系统记录、小幅情绪变化、当前场景焦点变化。
- 感觉、关系、身体状态、穿着状态、物品状态、性经历、性历史必须以明确事实为主，不能仅凭氛围暗示更新。
- 势力创建与势力字段补丁改由 Stage9 势力更新负责；本阶段不要输出势力总览、势力结构、组织能力。

输出硬规则：
- 首字符必须是 `{`，末字符必须是 `}`。
- 顶层 key 必须且只能包含“本次必须返回的类型”列出的类型；已完成类型不得重复输出；未列入类型不得输出。
- 顶层 key 必须按“必须输出 key 顺序”排列。
- 基础结算必须输出完整对象，必须包含：经过时间、当前状态、当前目标、场景标题、地点名称、备选行动。
- 备选行动必须是 4 个字符串组成的数组。
- 非基础类型必须输出数组；有稳定变化时写对象数组，无稳定变化时写 []。
- **角色卡四类身份字段例外**：仅处理本轮新确认或发生变化的稳定事实；本轮一旦确认社群角色、人事归属、证书或称号有事实或背景依据，就必须在对应类型中完整补全，不能因次要细节未逐字出现而输出 []。完全没有依据时才输出 []，且不得扫描或迁移本轮未变化的旧存档字段。
- 上述四类字段缺少次要细节时，依据本轮正文、已载入背景、世界观、年代、地区、教育或职业经历作最小充分推演；禁止与设定矛盾的扩张，也禁止“某公司”“未知学校”“相关机构”“普通职员”“初中生”“成员”等模糊占位。
- 每条更新只能写一个字段，禁止把字段合并成“当前地点/当前行动/可用状态”或“事件/记录/状态”。
- subject 必须直接写本回合参与者姓名、明确地点名、明确势力名或“系统”；不要写代词。
- reason/evidence 必须写具体行为、对话或连续动作证据；弱氛围暗示不得结算。
- 情绪、感觉、生命体征、性经历的 value/delta 必须是带符号非零变化，例如 +2 或 -1；没有变化输出 []。
- 情绪/感觉每条必须含 field、value、reason；**status** 写变化后程度表现（禁止“指标名+数值：”前缀），缺省则系统按新数值生成模板解释；reason 须与本质偏好五层相容，写清正文证据及与哪一层一致或形成何种张力。
- 情绪与感觉必须按“本轮参与者 + 正文证据”分别判断；若同一互动同时影响玩家和 NPC，分别输出两个主体的更新，不能只输出玩家一方。
- 感觉数组中 subject 只能写出场 NPC，不能写玩家姓名。
- 关系数组中 left/right/dimension/status/reason/result 都必须有；dimension 不能是好感/信任/依赖/警惕等感觉指标。
- 角色卡 op 只能写“替换”或“增加”；不能写保持、无变化、更新。
- 字符串中不要使用英文逗号或中文逗号分隔多字段；必要时用顿号或分号。
- 不要为了凑长度创造更新；空数组是合法完整输出。
