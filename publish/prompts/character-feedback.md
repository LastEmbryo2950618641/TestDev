# 初始角色反馈

生成角色本次被上线操控时的心理反馈，不创建、不覆盖情绪或关系数值。必须只返回合法 JSON，不要 Markdown。在生成数组时，遍历完最后一个元素后，立即停止添加逗号。记住：JSON 不允许尾随逗号。

## 模板构成拆分

1. 任务定位：角色在这一次被上线操控时的即时心理反馈；情绪与关系初始值只由角色卡 initialMetrics 创建。
2. 角色上下文：角色、年龄、操控方式、当前场景、人物资料。
3. 上线体验：历史上线次数、感觉、适应度、摘要、对控制者了解。
4. 上线体验规则块：基于上线次数与适应度生成的阶段规则。
5. 处境描述：身体失控、旁观、五感仍在。
6. mind：角色第一人称内心。
7. intent：角色本人想做什么。
8. choices：玩家可执行行动。
9. 输出格式：严格 JSON。

## 处境

角色突然失去身体控制权，只能在身体里旁观；仍能感到疼痛、疲劳、气味、触觉与周围环境变化。对控制者身份的认知必须服从“对控制者了解”字段当前等级，不得越级揭露。

## 对控制者了解（必填）

按认识程度三选一，并写不超过 20 字梗概：

1. `unknown`：不知道是谁在控制（最初默认）。梗概示例：尚不知晓控制者是谁。
2. `traitKnown`：对控制者品行/性格有所了解，但仍不知晓其真实身份与姓名。梗概示例：感到操控者冷静强势但不知是谁。
3. `identityGuessed`：知晓（或自认知晓）控制者是谁，但该判断不必与玩家真实身份完全一致，允许误认。梗概示例：怀疑控制者是某熟人。

mind / intent / controlFeeling 必须与所选等级一致：unknown 时禁止点名玩家真实姓名；traitKnown 时只写品行印象；identityGuessed 时可写其猜测身份。

## 字段规则

1. mind 必须是角色自己的第一人称内心独白，不写角色名，不写旁白。
2. intent 是角色本人想做什么，不是玩家选项。
3. controlFeeling 写角色对被上线操控的短语感受。
4. adaptation 写角色对上线操控的适应度变化或当前适应度。
5. experienceSummary 写 40 字内上线体验摘要。
6. controllerAwarenessLevel 只能是 unknown / traitKnown / identityGuessed。
7. controllerAwareness 写对控制者了解梗概，不超过 20 个汉字；须与 level 匹配。
8. choices 是玩家可执行行动，不能包含“放开控制”。
9. 不要返回 metricUpdates；角色卡创建阶段已经根据人物资料和备注生成 initialMetrics。
10. 如果人物资料里出现爱情、肉欲、依赖、亲情、占有等关系倾向，只能用于 mind、intent、controlFeeling 和 choices 的心理依据，不得在这里重置数值。
11. 必须先读取“上线体验规则块”，把其中关于阶段、经历深度与适应状态的信息转化成角色此刻的认知重点、身体感受、应对倾向与反应方式；不要直接复述规则块原文。
12. 相对已有“对控制者了解”，本轮可维持或合理推进一级，禁止无依据从 unknown 直接跳到 identityGuessed。

## 输出 JSON 格式

只返回一个 JSON 对象。字段规范如下：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| mind | string | 是 | 角色自己的第一人称内心独白，40 到 70 字。 |
| intent | string | 是 | 角色本人下一步想做什么，30 到 50 字。 |
| controlFeeling | string | 是 | 角色对被上线操控的短语感受。 |
| adaptation | number | 是 | 角色对上线操控的适应度变化或当前适应度。 |
| experienceSummary | string | 是 | 40 字内上线体验摘要。 |
| controllerAwarenessLevel | string | 是 | unknown / traitKnown / identityGuessed。 |
| controllerAwareness | string | 是 | 对控制者了解梗概，不超过 20 字。 |
| choices | array<string> | 是 | 玩家可执行行动，四项，每项 12 字内；不能包含“放开控制”。 |

不得返回 `metricUpdates`，不得创建或覆盖情绪与关系数值。
