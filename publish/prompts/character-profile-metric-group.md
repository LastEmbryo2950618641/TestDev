## 生成规则

1. 每一项都必须只有 `key`、`value`、`status`、`reason` 四个字段；`reason` 是强制字段，不能因为 status 已经很长就省略。
2. 字段顺序必须固定为 `key` → `value` → `status` → `reason`，每个对象都必须写完四个字段。
3. `reason` 必须写在同一个对象内部，禁止写成数组里的独立字符串或对象外字段；禁止出现 `},"reason"`、`],"reason"`、`"status":"..."}` 这类漏 reason 结构。
4. 每个对象必须以 `reason` 作为最后一个字段；写完 `reason` 后必须立刻用 `}` 结束当前对象，再用逗号进入下一个对象。
5. 禁止重复字段名，尤其禁止在同一对象里写两个 `key`、两个 `status` 或两个 `reason`；不要把下一个 key 写进当前对象。
6. 必须按“字段列表”和“完整 JSON 骨架”的顺序逐项生成，每个 key 精确出现一次，不能漏项、不能多项、不能改名。
7. `value` 是 0-100 数字，由 AI 按当前人物性格、处境、经历、关系证据、玩家资料、世界观和剧情事件判断，不得照抄默认值。
8. `status` 必须是 20-50 个汉字的短句，必须以当前 key 开头，使用“{当前key}因为……”或“{当前key}源于……”句式。
9. `reason` 必须是 20-50 个汉字的短句，必须以当前 key 开头，使用“{当前key}因为……”或“{当前key}源于……”句式。
10. `reason` 必须写形成该数值的具体原因，结合角色动机、处境与过去经历；不能和 status 完全重复，不能只写抽象性格词。
11. 证据弱或没有触发时 `value` 可以为 0，但也必须输出该 key，例如“嫉妒因为暂无竞争对象”。
12. 禁止写“默认、初始化、根据上下文、系统生成、综合判断、阶段定义、背景信息、个人动机与过去经历”等空话。
13. 不要返回英文 key、`initial_metrics`、`affection`、`dependency`、`trust_level` 等替代结构。
14. 输出过程按字段列表逐项完成：先写第1项，再写第2项，直到最后一项；禁止只写你认为最相关的项。
15. 只返回一行紧凑 JSON；不要 Markdown 代码块，不要换行，不要解释。

## 返回格式

只返回上方“完整 JSON 骨架”对应的完整对象。数组长度必须等于字段列表里的 key 数量；禁止只返回第一项，禁止额外补充其他 key。
