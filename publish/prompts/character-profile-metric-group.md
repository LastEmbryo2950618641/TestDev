## 生成规则

1. 每一项都必须只有 `key`、`value`、`status`、`reason` 四个字段；禁止重复字段名，尤其禁止在同一项里写两个 `status` 或两个 `reason`。
2. 必须按“字段列表”的顺序逐项生成，每个 key 精确出现一次，不能漏项、不能多项、不能改名。
3. `value` 是 0-100 数字，由 AI 按当前人物性格、处境、经历、关系证据、玩家资料、世界观和剧情事件判断，不得照抄默认值。
4. `status` 必须是完整句子，必须点名该 key 本身，解释“为什么这个 key 是当前数值”。例如 key 是“高兴”时，status 里必须出现“高兴”或“愉快/满足/开心”等同义词，并结合具体证据。
5. `reason` 必须是完整句子，必须写形成该数值的具体原因，结合角色动机、处境与过去经历；不能和 status 完全重复。
6. 证据弱或没有触发时 `value` 可以为 0，但 `status/reason` 也必须说明缺少哪类证据，不能留空。
7. 禁止写“默认、初始化、根据上下文、系统生成、综合判断、阶段定义、背景信息”等空话。
8. 不要返回英文 key、`initial_metrics`、`affection`、`dependency`、`trust_level` 等替代结构。
9. 只返回一行紧凑 JSON；不要 Markdown 代码块，不要换行，不要解释。

## 返回格式

```json
{"{根字段}":[{"key":"{首个字段}","value":0,"status":"具体解释","reason":"具体原因"}]}
```
