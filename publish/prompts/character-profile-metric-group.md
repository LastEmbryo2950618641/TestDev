## 生成规则

1. 每一项都必须只有 `key`、`value`、`status`、`reason` 四个字段；写完 `reason` 后必须立刻用 `}` 结束当前对象，再用逗号进入下一个对象。
2. 禁止重复字段名，尤其禁止在同一对象里写两个 `key`、两个 `status` 或两个 `reason`；不要把下一个 key 写进当前对象。
3. 必须按“字段列表”和“完整 JSON 骨架”的顺序逐项生成，每个 key 精确出现一次，不能漏项、不能多项、不能改名。
4. `value` 是 0-100 数字，由 AI 按当前人物性格、处境、经历、关系证据、玩家资料、世界观和剧情事件判断，不得照抄默认值。
5. `status` 必须是 18-45 个汉字的完整句子，必须使用“{当前key}因为……”或“{当前key}源于……”句式，解释“为什么这个 key 是当前数值”。例如 key 是“了解”时写“了解因为共同生活多年积累出具体生活认知”。
6. `reason` 必须是 18-55 个汉字的完整句子，必须使用“{当前key}因为……”或“{当前key}源于……”句式，包含具体因果或证据；例如不要写“坚强的性格支撑”，要写“冷静源于她长期照顾妹妹时练出的压抑反应”。
7. `reason` 必须写形成该数值的具体原因，结合角色动机、处境与过去经历；不能和 status 完全重复，不能只写抽象性格词。
8. 证据弱或没有触发时 `value` 可以为 0，但 `status/reason` 也必须说明缺少哪类证据，不能留空，例如“嫉妒为0，因为当前关系里没有竞争对象”。
9. 禁止写“默认、初始化、根据上下文、系统生成、综合判断、阶段定义、背景信息、个人动机与过去经历”等空话。
10. 不要返回英文 key、`initial_metrics`、`affection`、`dependency`、`trust_level` 等替代结构。
11. 只返回一行紧凑 JSON；不要 Markdown 代码块，不要换行，不要解释。

## 返回格式

```json
{"{根字段}":[{"key":"{首个字段}","value":0,"status":"具体解释","reason":"具体原因"}]}
```
