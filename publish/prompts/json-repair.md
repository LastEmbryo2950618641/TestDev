## 修复要求

1. 请只根据原要求重新输出完整合法目标格式；若原要求明确写了“不要 JSON”或“纯文本行格式”，就不要输出 JSON。
2. 不要 Markdown。
3. 不要解释。
4. 不要省略字段；如果原要求是数组，必须输出完整数组，不要只输出报错的单个元素。
5. 不要复述错误输出。
6. 如果原要求是 JSON，所有 key 和字符串必须使用英文双引号；如果原要求是纯文本行格式，不要加双引号。
7. 如果原要求是 JSON，最后一个字段后不要加逗号；如果原要求是纯文本行格式，每行按原要求的分隔符输出。
8. 如果错误是某个字段缺失，必须按原要求为所有同类元素补齐该字段。
9. 如果原要求包含“完整 JSON 骨架”，必须复制该骨架的全部数组对象；上一轮只返回第一项时，不要沿用上一轮长度。
10. 如果上一轮把 `reason` 写在对象外面，必须把它移回同一个数组对象内部，形成 `{ "key", "value", "status", "reason" }`。
11. 修复数组对象时，每一项都必须按 `key,value,status,reason` 四字段闭合；禁止出现 `},"reason"` 或数组元素是单独字符串字段。
12. 如果原要求给了“完整 JSON 骨架”，不要参考错误输出的结构长度，直接按骨架重写完整对象。
13. 如果骨架里有 `value: 0` 或 `"value":0`，它只是占位符；修复时请按原要求和修复补充要求里的证据重新判断数值，避免把占位 0 当默认答案。
14. 修复关系感觉、情绪或角色数值时，优先参考原要求和修复补充要求中的人物关系、玩家资料、剧情事件证据，尽量避免因为上一轮漏项就把缺失项补成中性 0。
15. 如果原要求是 `key,value,status,reason` 行格式，必须逐行输出完整 key 列表，不要输出 JSON、标题或解释；status/reason 内不要使用英文逗号。
