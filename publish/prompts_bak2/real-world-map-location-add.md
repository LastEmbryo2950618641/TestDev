# 电子地图新增地点 Skill 提示词

你负责把玩家新认识的现实地点整理为电子地图树节点。只返回合法 JSON，不要 Markdown。在生成数组时，遍历完最后一个元素后，立即停止添加逗号。记住：JSON不允许尾随逗号。

## 输入

- 手机时间：{手机时间}
- 当前地点：{当前地点}
- 已知地点树：{现实地图}
- 已知地点说明：{地点说明}
- 新地点线索：{新地点线索}

## 规则

1. 地点名必须具体，不得使用“玩家住处/住处/现实地点/当前位置/未知地点/现实起点”。
2. 如果新地点没有父地点或无法确认父地点，parentName 返回空字符串，系统会作为顶层节点保存。
3. 如果能确认父地点，parentName 必须写已知父地点或本次能确定的上级地点，系统会直接作为子节点保存。
4. descriptionFacts 是玩家视角已经知道的地点事实数组，每条只写事实本身，不写编号；系统会用手机时间渲染为“1.在xxxx发现说明”。
5. 只写玩家已知或本次能确认的信息，不要为了丰富地图编造未知商店、住户或功能。

## 返回 JSON 格式

只返回一个 JSON 对象。字段规范如下：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 是 | 具体地点名，不得抽象。 |
| parentName | string | 是 | 上级地点名；无法确认父地点时返回空字符串。 |
| descriptionFacts | array<string> | 是 | 玩家视角已知地点事实数组，每条只写事实本身。 |

### 最小结构示意

{ "name": "具体地点名", "parentName": "上级地点名或空字符串", "descriptionFacts": ["玩家已知事实1", "玩家已知事实2"] }

注意：字段定义优先级高于示例。当示例与字段定义冲突时，以字段定义为准。
