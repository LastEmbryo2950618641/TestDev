# Workspace Noise Governance Plan (2026-07-12)

This plan defines the next safe path for reducing long-lived worktree noise without deleting useful host evidence or accidentally hiding real source-of-truth changes.

## Goal
Reduce repeat worktree pollution caused by generated artifacts, mirrored runtime materialization, and local machine files while preserving the current multi-platform assembly model.

## Current noise classes
### Class 1: tracked generated artifacts
Current example:
- `publish/platform/.artifacts/unified-platform-readiness.json`

Characteristics:
- generated by report scripts
- can change even when gameplay/runtime meaning does not
- can pollute unrelated commits with timestamp-only diffs

### Class 2: tracked mirrored Android assembly files
Current example:
- `mobile/android-webview-shell/app/src/main/assets/publish/index.html`

Characteristics:
- belongs to Android materialized assembly input
- not the shared runtime source of truth
- may still appear as tracked diff after sync or mirror refresh

### Class 3: local machine and run-residue files
Current examples:
- `mobile/android-webview-shell/.artifacts/`
- `mobile/android-webview-shell/.last-asset-sync.json`
- `mobile/android-webview-shell/.last-build-attempt.json`
- `mobile/android-webview-shell/local.properties`
- `mobile/android-webview-shell/local.properties.generated`

Characteristics:
- local-only or execution-residue state
- useful for one machine or one run, but usually not durable source
- should not continuously distract normal implementation work

## Safe governance rules
1. Do not treat worktree noise reduction as permission to delete mirrored runtime inputs blindly.
2. Keep source-of-truth policy separate from ignore policy.
3. Prefer documenting class-by-class handling before changing git tracking behavior.
4. Avoid mixing noise-governance commits with gameplay or host-implementation commits.

## Recommended handling by class
### Class 1: tracked generated artifacts
Recommended direction:
- keep artifact policy explicit
- prefer no-artifact-write verification flows when possible
- avoid staging artifact-only diffs in unrelated commits
- decide later whether tracked report artifacts should remain milestone evidence only

### Class 2: tracked Android mirror
Recommended direction:
- preserve current source-of-truth rule: root `publish/` is authoritative
- treat Android assets under `app/src/main/assets/publish/` as materialized assembly input
- do not manually edit mirror-only files as if they were primary source
- decide later whether mirror tracking should remain explicit or move to a stricter sync-based policy

### Class 3: local machine and run-residue files
Recommended direction:
- classify local-only files separately from reproducible shell inputs
- prefer ignore policy or local-only handling for machine-bound files
- keep durable examples such as `local.properties.example`, but avoid normalizing machine-specific variants into source control without reason

## Immediate next pass
The safest next noise-governance pass should happen in this order:
1. record the class-based governance model
2. identify which Class 3 files are safe ignore candidates
3. verify whether any Class 2 tracked diffs are content-identical mirror refreshes only
4. revisit Class 1 tracked artifact policy after current documentation promotion work stabilizes

## Current recommendation
Do not rush into a broad ignore or deletion sweep.
Start by stabilizing the governance model and then take one noise class at a time.
That preserves low-coupling architecture work while making the worktree progressively cleaner.
