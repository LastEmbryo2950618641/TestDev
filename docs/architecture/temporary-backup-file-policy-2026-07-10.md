# 临时备份文件处理说明 2026-07-10

## 目的

这份说明用于告诉后续会话：哪些临时修复痕迹不是正式架构的一部分，为什么它们会出现，以及在什么前提下才能处理它们。

## 当前已知临时修复痕迹

### `publish/worldline-actions.js.bak`

来源：
- 在 `worldline` UI helper 抽离过程中，旧文件曾出现结构损坏风险。
- 当时保留该备份，用于快速比对和手工回填丢失片段。

当前地位：
- 不是正式运行入口。
- 不应继续在其上追加新逻辑。
- 后续如果正式文件与修复说明都稳定，可在确认不再需要人工比对后移除。

关联说明：
- `docs/plans/2026-07-10-worldline-ui-repair-note.md`

### `publish/settings-actions.js.bak2`

来源：
- 在 `settings` UI helper 迁移时，局部 helper cluster 曾因多次相邻替换而变得不稳定。
- 该备份用于对照修复前后差异，避免再次丢失局部逻辑。

当前地位：
- 不是正式运行入口。
- 不应继续在其上追加新逻辑。
- 后续如果正式文件与修复说明都稳定，可在确认不再需要人工比对后移除。

关联说明：
- `docs/plans/2026-07-10-settings-ui-repair-note.md`

## 当前处理规则

- 后续 AI 会话不得把 `.bak` / `.bak2` 当成真实实现继续扩展。
- 如需核对历史片段，只能把它们当只读对照材料。
- 任何新的目录规范化工作，应该以正式运行文件和修复说明文档为准。
- 如果未来决定删除这些备份文件，应在同一次改动中说明删除依据，避免后续会话误以为缺失上下文。

## 当前结论

这些备份文件属于修复过程遗留物，不属于正式架构层。

后续目录规范化与多端边界收敛，应继续围绕：
- `publish/app/`
- `publish/domain/`
- `publish/platform/`
- `publish/ui/`
- `docs/plans/` / `docs/architecture/`

而不是围绕临时备份文件继续演化。
