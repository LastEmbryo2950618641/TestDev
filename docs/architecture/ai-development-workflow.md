## 9. 展示层优先收口工作流（2026-07-11 补充）

当需求落在高耦合页面模块，但当前目标仍是低风险推进时，默认先走展示层收口流程。

执行顺序：

1. 先判断本轮是否只涉及展示派生
2. 若可以只动展示，则优先抽 `title / subtitle / empty-state / row / card / dialog view`
3. 真正实现进入 `publish/ui/<module>/...`
4. 旧入口只保留兼容转发
5. 模板改为消费 helper 对象，不直接拼状态和文案
6. 每次只收一个相邻展示切面
7. 改完后立即做最小验证与文档同步

本流程默认不与以下内容混在同一轮：

- 消息发送与接收主链
- 记忆写回
- 同步、恢复、初始化入口
- 异步图片生成与流程装配
- 跨页面隐式状态写入

停手条件：

- 一旦发现下一刀将进入写状态主链，就先停在展示层
- 一旦发现需要跨多个高风险旧文件同时改动，就先回到计划文档
- 一旦发现编码或模板结构风险扩大，就先缩小修改面

最小验收：

- helper 已新增且可检索
- 兼容壳已接好
- 模板已实际消费新 helper
- `node --check` 通过
- 边界文档或 playbook 已同步更新
