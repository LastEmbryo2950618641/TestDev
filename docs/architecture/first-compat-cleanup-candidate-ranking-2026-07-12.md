# First Compat Cleanup Candidate Ranking (2026-07-12)

## 目的

基于当前已经形成的 bridge inventory、模板消费审计、模板迁移准备样板与 gate 预审，给出第一版“首批 compat 清理候选排序结论”。

这份文档不等于立即删除任何 compat 入口，而是回答：

- 当前哪些模块最接近进入 compat 删除 gate 评估
- 哪些模块更适合作为迁移样板，而不是删除候选
- 哪些模块当前仍应继续收口、暂不考虑清理

## 排序标准

当前排序主要参考以下维度：

1. 模板公开面是否已经收缩
2. Web / Android 镜像消费是否集中且一致
3. 模块内部实现是否已较稳定地下沉到模块侧
4. 是否仍存在高副作用动作链耦合
5. `game.js` 上 compat 入口是否仍承担明显兜底职责

## 当前排序结论

### 第 1 位：calendar

当前定位：`最接近进入 compat 删除 gate 评估的对照模块`

理由：

1. 模板主显示面已经较集中到 `calendarPanelView()`
2. 模板动作入口目前主要只剩 `changeCalendarMonth(delta)`
3. 只读/派生能力已在 `calendarActions` / `viewHelpers` 中较稳定
4. Web / Android 镜像消费方式一致
5. 相比其他模块，它最接近“view contract + 少量动作入口”的成熟形态

当前仍缺：

- `calendarPanelView()` / `changeCalendarMonth()` 的长期公开面定位
- 模板外调用面补全审计
- `calendarMonthTitle()` / `calendarDays()` fallback 是否仍有必要的判断

结论：

- `calendar` 不是立即删除对象
- 但它是当前最适合继续做 compat 删除 gate 深化评估的第一候选

### 第 2 位：skills

当前定位：`迁移准备样板优先模块，尚不适合率先删 compat`

理由：

1. 只读查询面已完成桥接
2. 模板消费区块集中
3. Web / Android 镜像消费一致
4. 模块规模较小，验证成本相对可控

限制：

1. 模板仍直接依赖多个 `$store.game.skills...` 入口
2. 详情弹层动作仍暴露在模板公开面上
3. `skillsState.detailOpen` 等状态仍直接参与模板交互

结论：

- `skills` 适合继续做模板迁移准备与动作/读取面拆分样板
- 当前不应作为第一批真实 compat 删除候选

### 第 3 位：prompt

当前定位：`轻交互模板迁移样板模块`

理由：

1. 展示面与轻交互动作面边界较清楚
2. Web / Android 镜像模板结构对齐
3. 已形成只读展示面 + 动作面分批迁移思路

限制：

1. 模板仍直接依赖较多 `$store.game.prompt...` 入口
2. 弹层详情、筛选、选中状态都还直接与模板交互
3. 相比 `skills`，它的轻交互状态复杂度更高一些

结论：

- `prompt` 很适合作为第二批迁移准备样板
- 当前仍不适合作为首批 compat 删除候选

### 第 4 位：boss

当前定位：`复杂模块的展示/派生面收口样板`

理由：

1. 一批只读展示/派生入口已完成桥接
2. 复杂模块也证明了 compat facade 收口路线可行

限制：

1. 生成、预约、申请、落日历、公司同步等动作链仍复杂
2. 模板消费面广
3. 高副作用路径明显多于轻量模块

结论：

- `boss` 当前应继续停留在“展示/派生面收口”阶段
- 暂不考虑进入首批 compat 删除候选

### 第 5 位：taobao

当前定位：`模板消费广、公开面厚的长期收口模块`

理由：

1. 桥接工作已完成一批
2. 模块实现已经分散到 `actions` / `domain` / `viewHelpers`

限制：

1. 模板直接消费面很广
2. 详情、筛选、购买等路径交织更深
3. 继续推进删除前需要更大规模模板迁移准备

结论：

- `taobao` 当前不适合作为首批 compat 删除试点
- 更适合继续维持模式 A：保留 contract，持续瘦身实现

## 当前阶段推荐顺序

### 第一阶段：继续做 gate 预审深化

优先顺序：

1. `calendar`
2. `skills`
3. `prompt`

目标：
- 继续补齐“是否有资格进入删除 gate”的证据，而不是直接删

### 第二阶段：继续做迁移准备样板

优先顺序：

1. `skills`
2. `prompt`
3. `calendar`（作为完成态对照）

目标：
- 明确哪些模块适合真正迁模板
- 明确哪些模块更适合长期保留 facade

### 第三阶段：暂缓进入清理的模块

当前应暂缓：

1. `boss`
2. `taobao`

目标：
- 继续扩展示示/派生面收口
- 暂不提早进入 compat 删除讨论

## 当前总判断

当前最合理的首批 compat 清理路线，不是马上删除某个模块的入口，而是：

1. 把 `calendar` 作为第一预审对照模块继续深化
2. 把 `skills`、`prompt` 作为迁移准备样板模块继续完善
3. 把 `boss`、`taobao` 继续留在“收口优先、删除后置”的轨道上

## 当前结论

如果必须给出一版当前阶段排序：

1. `calendar`：最接近进入 compat 删除 gate 评估
2. `skills`：最适合继续完善迁移准备样板
3. `prompt`：次优先的轻交互迁移准备样板
4. `boss`：复杂模块展示面收口样板
5. `taobao`：长期收口模块，当前不宜提早进删除阶段

这份排序的意义在于：

- 后续推进不再依赖临场判断
- 每个模块的“下一步应该做什么”已有相对清晰的定位
- 可以开始围绕第一候选模块持续积累删除 gate 证据，而不是继续平均发力
