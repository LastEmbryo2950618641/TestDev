## 13. 展示层优先收口规则（2026-07-11 补充）

当后续 AI 会话处理高耦合页面模块时，默认优先采用“展示层先收口”的低风险路径。

推荐顺序：

1. 先抽 `title / subtitle / empty-state`
2. 再抽 `row` 列表对象
3. 再抽 `card` / `view object`
4. 再抽弹窗文案与工具栏展示对象
5. 最后才评估是否需要进入 `domain/<module>`

默认不要在同一轮混入以下高风险区域：

- 消息发送与接收主链
- 记忆写回
- 同步、恢复、初始化入口
- 图片生成、异步流程装配
- 跨页面隐式状态写入

推荐实现方式：

- 真正实现进入 `publish/ui/<module>/...`
- 旧入口文件只保留兼容转发
- 模板逐步改为消费 helper 对象，而不是直接拼状态和中文文案
- 每次只收一个相邻展示切面

最小验证要求：

- helper 文件可检索到新增方法
- 旧入口存在对应兼容壳
- 模板已实际消费新 helper
- `node --check` 通过
- 文档同步记录本轮边界与停手位置

编码与命令层注意点：

- PowerShell 中避免直接写包含 `${}`` 的复杂模板字符串
- 中文大文件优先做小范围增量替换，不做整份重写
- 修改 `index.html` 这类大模板后，要顺手检查邻近闭合标签是否完整
