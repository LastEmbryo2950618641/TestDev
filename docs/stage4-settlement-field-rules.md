# Stage4 结算字段与赋值规则

本文档定义现实推演 Stage4 中文 K:V 结算中，各结算类型允许写入的字段、赋值规则和字段含义。目标是让提示词、解析器和更新链路使用同一套字段边界，避免模型随机创造字段或把事实写入错误类型。

## 通用结算原则

1. 每条更新必须有明确结算主体。
   - 角色主体：使用角色姓名或角色 ID。
   - 玩家主体：使用玩家姓名或 `player-self`。
   - 地点、势力、系统主体：只用于对应类型，不得写入角色卡。
2. 非“基础结算”类型没有明确稳定事实时写 `无变化`。
3. 更新行中的“变化原因”必须说明本轮正文、行动或已加载资料中支持该更新的依据。
4. 若同一个事实有专门类型，必须写入专门类型，不要落到“通用固化”。例如穿着写“穿着状态”，身体写“身体状态”，生命体征写“生命体征”。
5. 数值增减统一使用 `+N` / `-N`；文本状态统一写新状态文本。

## 1. 基础结算

### 允许字段

| 字段 | 赋值格式 | 含义 |
| --- | --- | --- |
| 经过时间 | 秒数，整数 | 本轮行动在现实时间中经过的秒数。 |
| 当前状态 | 文本 | 本轮结束后玩家当前可见状态。 |
| 当前目标 | 文本 | 本轮结束后玩家下一步主要目标。 |
| 场景标题 | 文本 | 当前场景的短标题。 |
| 地点名称 | 地点全称 | 当前所在地点。 |
| 备选行动1 | 行动文本 | 下一轮可选行动。 |
| 备选行动2 | 行动文本 | 下一轮可选行动。 |
| 备选行动3 | 行动文本 | 下一轮可选行动。 |
| 备选行动4 | 行动文本 | 下一轮可选行动。 |

### 赋值规则

- 基础结算必须完整输出所有字段，不能写 `无变化`。
- `经过时间`只写数字，不写“约”“分钟”等含糊单位。
- 备选行动必须能被玩家直接选择执行。

## 2. 情绪结算

### 允许字段

字段只能是该结算主体当前已有的情绪指标名。常见结构是：

| 字段来源 | 赋值格式 | 含义 |
| --- | --- | --- |
| 紧张 | `+N` / `-N` | 主体当前紧张程度变化。 |
| 恐惧 | `+N` / `-N` | 主体当前恐惧程度变化。 |
| 愤怒 | `+N` / `-N` | 主体当前愤怒程度变化。 |
| 悲伤 | `+N` / `-N` | 主体当前悲伤程度变化。 |
| 安心 | `+N` / `-N` | 主体当前安心程度变化。 |
| 好奇 | `+N` / `-N` | 主体当前好奇程度变化。 |
| 其他已存在情绪名 | `+N` / `-N` | 角色卡中已经存在的情绪指标。 |

### 赋值规则

- 只能写“当前情绪基线”里已经出现的字段名。
- 不得新造情绪字段。
- 主体可以是玩家，也可以是出场 NPC。
- 只记录本轮明确造成的情绪变化。
- 没有对应已有指标时写 `无变化`。
- 但AI可能随便给不存在的值，因此需要建立一个映射字典，即愉悦 -> 高兴。

### 更新格式

```text
更新N：结算主体，情绪名，+/-数值，变化原因
```

## 3. 感觉结算

### 允许字段

字段只能是出场角色当前已有的“对玩家感觉”指标名。常见结构是：

| 字段来源 | 赋值格式 | 含义 |
| --- | --- | --- |
| 信任 | `+N` / `-N` | 该角色对玩家的信任变化。 |
| 好感 | `+N` / `-N` | 该角色对玩家的好感变化。 |
| 依赖 | `+N` / `-N` | 该角色对玩家的依赖变化。 |
| 警惕 | `+N` / `-N` | 该角色对玩家的警惕变化。 |
| 畏惧 | `+N` / `-N` | 该角色对玩家的畏惧变化。 |
| 反感 | `+N` / `-N` | 该角色对玩家的反感变化。 |
| 其他已存在感觉名 | `+N` / `-N` | 角色卡中已经存在的对玩家感觉指标。 |

### 赋值规则

- 主体只能是出场 NPC，不能是玩家本人。
- 字段只能使用“出场角色对玩家感觉基线”里已经出现的字段名。
- 不得新造感觉字段。
- 只记录角色对玩家的态度变化，不记录玩家自我感受。
- 没有对应已有指标时写 `无变化`。
- 但AI可能随便给不存在的值，因此需要建立一个映射字典，即信赖 ->信任。


### 更新格式

```text
更新N：结算主体，感觉名，+/-数值，变化原因
```

## 4. 生命体征结算

### 允许字段

| 中文字段 | 中文别名 | 写入路径 | 赋值格式 | 含义 |
| --- | --- | --- | --- | --- |
| 生命力 | 生命值、健康、health | `vitals.vitality` | `+N` / `-N` | 当前承伤、生存与身体完整状态。 |
| 精力 | 精力池、体力、stamina | `vitals.stamina_pool` | `+N` / `-N` | 可用体力、行动精力池。 |
| 饱食度 | 饱食、satiety | `vitals.satiety` | `+N` / `-N` | 饥饿/饱腹状态。 |
| 水分 | 口渴、水合、hydration | `vitals.hydration` | `+N` / `-N` | 口渴、补水、脱水相关状态。 |
| 疲劳 | 疲劳度、fatigue | `vitals.fatigue` | `+N` / `-N` | 疲惫累积程度。 |
| 精神稳定 | 精神稳定度、mental_stability | `vitals.mental_stability` | `+N` / `-N` | 精神稳定度、清醒稳定程度。 |

### 不允许字段

以下字段不属于当前生命体征结算字段，不应写入：

- 心率
- 体温
- 呼吸频率
- 血压
- 血氧
- 瞳孔
- 激素
- 学习能力
- 成长潜力
- 行动能力
- 任何未列入上表的新指标

### 赋值规则

- 生命体征只接受上表 6 个中文字段及其中文别名。
- 变化值必须是数值增减，例如 `+5`、`-3`。
- `生命力 +N` 表示伤势恢复或生存状态改善；`生命力 -N` 表示受伤、疾病、损害或身体完整状态下降。
- `疲劳 +N` 表示更疲劳；`疲劳 -N` 表示疲劳降低。
- `精力/饱食度/水分/精神稳定 +N` 表示对应状态提升；`-N` 表示降低。
- `health` 只能作为“生命力”的输入别名映射到 `vitals.vitality`；最终结算字段不写 `health`。
- `精力池` 和 `疲劳度` 是旧 UI/旧结算链路里的显示名，必须分别归一化为 `精力` 和 `疲劳`。
- 没有明确生命力、体力、饥渴、疲劳或精神稳定变化时写 `无变化`。

### 更新格式

```text
更新N：结算主体，字段名，+/-数值，变化原因
```

## 5. 身体状态结算

### 允许身体部位字段

| 中文部位/状态键 | 标准键 | 含义 |
| --- | --- | --- |
| 整体 / 全身 | `overall` | 整体身体状态。 |
| 口部 / 嘴部 / 嘴唇 | `mouth` | 口部状态。 |
| 胸部 / 胸口 / 乳房 | `chest` | 胸部状态。 |
| 阴部 / 私处 | `genital` | 阴部状态。 |
| 肛部 | `anus` | 肛部状态。 |
| 臀部 / 屁股 | `hips` | 臀部状态。 |
| 四肢 / 手臂 / 腿部 | `limbs` | 四肢状态。 |
| 皮肤 | `skin` | 皮肤表面状态。 |
| 其他 | `other` | 无法归入以上部位但角色卡已有的其他身体状态。 |
| 已有身体状态键 | 原键名 | 当前角色卡中已经存在的其他身体状态键。 |

### 赋值规则

- 只能写已有身体状态键，或上表可归一化到标准键的身体部位。
- 只能记录明确身体状态变化。
- 状态值写“新状态”，不是数值增减。
- 状态值应描述本轮结束后该部位当前状态。
- 没有明确变化时写 `无变化`。

### 更新格式

```text
更新N：结算主体，部位或状态键，新状态，变化原因
```

## 6. 穿着状态结算

### 允许穿着部位/槽位

| 中文部位 | 标准槽位 | 含义 |
| --- | --- | --- |
| 胸部 / 胸口 / 乳房 | `bra` | 胸部内衣或覆盖胸部的局部衣物状态。 |
| 上身 | `top` | 上身主衣物，例如衬衫、T 恤、上衣。 |
| 外套 | `outerwear` | 外层衣物，例如外套、夹克、开衫。 |
| 下身 | `bottom` | 下身主衣物，例如裤子、裙子。 |
| 腿部 / 大腿 | `legwear` | 袜子、连裤袜、腿部穿戴。 |
| 足部 / 脚部 | `shoes` | 鞋、拖鞋、袜鞋类。 |
| 内裤 | `panties` | 下身内衣。 |
| 饰品 | `饰品` | 项链、手环、脚环、戒指、耳环、腿圈、项圈等饰品。 |
| 当前已有槽位 | 原槽位 | 角色卡中已经存在的穿着槽位。 |

### 衣物名称字段

| 字段 | 赋值格式 | 含义 |
| --- | --- | --- |
| 衣物名称 | 文本 | 具体衣物或饰品名称，例如“黑色百褶短裙”“白色衬衫”“银色手链”。 |

### 当前状态字段

| 状态类型 | 赋值示例 | 含义 |
| --- | --- | --- |
| 正常穿着 | `正常穿着` | 衣物仍处于原本穿戴状态。 |
| 已脱下 | `已脱下` | 衣物被脱下，不再穿在对应部位。 |
| 已换成 | `已换成：新衣物名` | 发生明确换装。 |
| 局部移位 | `被拉开` / `滑落` / `卷起` / `解开` | 衣物位置或闭合状态变化。 |
| 损坏 | `破损` / `撕裂` / `污损` | 衣物物理状态变化。 |
| 持有但未穿 | `拿在手中` / `放在床边` | 衣物从穿戴变为持有或放置。 |

### 赋值规则

- 穿着状态必须包含：结算主体、穿着部位、衣物名称、当前状态、变化原因。
- 穿着部位必须能归入上表槽位，或是角色卡当前已有槽位。
- 衣物名称应优先沿用角色卡当前穿着中的名称。
- 只有正文或资料明确发生穿脱、换装、移位、损坏、拿取、放置时才更新。
- 如果只是正文提到“看到某人穿着某衣物”，但该衣物已经是当前穿着，不需要更新。
- 如果没有明确换装事实，不得把当前衣物替换成另一件新衣物。

### 更新格式

```text
更新N：结算主体，穿着部位，衣物名称，当前状态，变化原因
```

- 分类必须使用上表中文分类或其别名。
- 变化值必须是数值增减。
- “总次数/总数/全部”不纳入 AI 计算，AI 只写具体分类次数。
- 写具体分类时只改变对应分类次数；总次数由后续汇总逻辑根据分类次数累加或展示层计算。
- 变化原因必须说明为什么本轮能确认次数变化。
- 没有明确次数变化时写 `无变化`。

### 更新格式

```text
更新N：结算主体，分类，+/-数值，变化原因
```

## 8. 性历史结算

### 允许字段

当前 Stage4 K:V 的性历史结算统一写入：

| 字段 | 赋值格式 | 含义 |
| --- | --- | --- |
| `intimacy.sexualHistory.transition` | 状态转移文本 | 性历史状态如何变化。 |
| `intimacy.sexualHistory.partner` | 性对象 | 与该状态转移相关的对象。 |
| `intimacy.sexualHistory.evidence` | 原因与证据 | 支撑状态转移的明确证据。 |
| `intimacy.sexualHistory.historyText` | 自动组合文本 | 由“状态转移、性对象、原因与证据”组成的摘要。 |

更新链路还识别以下细分字段，作为结构化性历史资料：

| 字段 | 赋值格式 | 含义 |
| --- | --- | --- |
| `intimacy.sexualHistory.virginityStatus` | `处女` / `非处女` / 其他明确状态 | 当前处女状态。 |
| `intimacy.sexualHistory.virginityEvidence` | 文本 | 处女状态证据。 |
| `intimacy.sexualHistory.firstVaginalPartner` | 对象 | 首次阴道经历对象。 |
| `intimacy.sexualHistory.firstVaginalAt` | 时间文本 | 首次阴道经历发生时间。 |
| `intimacy.sexualHistory.firstVaginalEvidence` | 文本 | 首次阴道经历证据。 |
| `intimacy.sexualHistory.defloweredPartners` | 对象列表 | 成为对方初体验对象的记录。 |
| `intimacy.sexualPartnerCount` | 整数 | 性对象数量。 |

### 赋值规则

- K:V 格式只写“状态转移、性对象、原因与证据”。
- 状态转移必须是明确历史状态变化，例如“处女→非处女”“新增首次对象记录”。
- 性对象必须是明确对象名称或 ID。
- 原因与证据必须能支撑状态转移。
- 不得把“性经历次数”的分类计数写到性历史；次数变化写“性经历”。
- 没有明确历史状态变化时写 `无变化`。

### 更新格式

```text
更新N：结算主体，状态转移，性对象，原因与证据
```

## 9. 关系结算

### 允许字段

关系结算写入关系维度：

| 字段 | 赋值格式 | 含义 |
| --- | --- | --- |
| 甲方(称谓) | 文本 | 关系的一方，可写姓名、玩家称谓或角色称谓。 |
| 乙方(称谓) | 文本 | 关系的另一方。 |
| 维度 | 文本 | 关系类别，例如亲属、朋友、同事、师生、雇佣、敌对、同居、恋人等。 |
| 当前状态 | 文本 | 该关系维度下当前稳定状态。 |
| 变化原因 | 文本 | 关系变化原因。 |
| 根据性格造成结果 | 文本 | 结合角色性格后的关系表现结果。 |

### 赋值规则

- 维度会写入 `relationships.维度`。
- 当前状态应是关系状态，不是情绪或感觉数值。
- 只有称谓、承诺、身份关系、合作/敌对关系、长期相处关系发生明确变化时才更新。
- 短暂情绪变化写“情绪”；对玩家态度数值写“感觉”。
- 没有稳定关系变化时写 `无变化`。

### 更新格式

```text
更新N：结算主体，甲方(称谓)，乙方(称谓)，维度，当前状态，变化原因，根据性格造成结果
```

## 10. 角色卡结算

### 允许字段

角色卡结算写入 `profile` 或状态标签。允许字段如下：

| 中文字段 | 写入方式 | 赋值格式 | 含义 |
| --- | --- | --- | --- |
| 当前状态 | `status_tags` | 文本标签 | 角色当前稳定状态标签。 |
| 身份 | `profile.身份` | 文本 | 角色身份、社会身份、剧情身份。 |
| 职业 | `profile.职业` | 文本 | 角色职业。 |
| 技能 | `profile.技能` | 文本或条目 | 角色已确认技能。 |
| 知识 | `profile.知识` | 文本或条目 | 角色已确认知识。 |
| 外貌 | `profile.外貌` | 文本 | 稳定外貌设定。 |
| 性格 | `profile.性格` | 文本 | 稳定性格设定。 |
| 喜好 | `profile.喜好` | 文本 | 稳定喜好。 |
| 人物说明 | `profile.人物说明` | 文本 | 角色说明补充。 |
| 社群角色 | `profile.社群角色` | 文本 | 在社群中的角色。 |
| 势力地位 | `profile.势力地位` | 文本 | 在势力或组织中的地位。 |
| 人际关系 | `profile.人际关系` | 文本 | 角色卡文本型人际关系摘要。结构化关系应优先写“关系结算”。 |
| 其他明确角色卡字段 | `profile.字段名` | 文本 | 已确认属于角色卡的稳定字段。 |

### 操作类型

| 操作 | 含义 |
| --- | --- |
| 替换 | 用新值覆盖该字段。 |


## Stage3 角色卡资料拼接要求

`loadedNarrationSummary()` 对角色卡资料不应按关键词过滤字段。角色卡资料进入正文生成时，应把本轮加载到的角色卡内容拼接成完整文本块，让 Stage3 能看到当前穿着、身份、地点、状态、技能、职业、知识等字段。

### 拼接规则

1. 如果资料是角色卡，保留角色卡原有字段顺序。
2. 不删除穿着、外貌、职业、技能、知识、物品、身体状态、生命体征、情绪、对玩家感觉等字段。
3. 只做长度控制(1000字 - 1500字)，不做字段级过滤。
4. 多张角色卡按资料顺序拼接。
5. 非角色卡资料仍可按当前摘要规则压缩。

### 目的

- 防止正文阶段缺少当前穿着而随机生成衣物。
- 防止正文阶段缺少职业、技能、知识而随机补设定。
- 让 Stage3 正文和 Stage4 结算使用一致的资料基础。
