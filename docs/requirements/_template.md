# 需求文档模板

> 文件位置：`docs/requirements/YYYY-MM-DD-功能名-requirement.md`

## 1. 背景

说明这次需求出现的背景、当前问题、触发原因。

## 2. 用户目标

说明用户真正想达到什么效果。

## 3. 预期行为

列出修改后系统应该表现出的行为。

建议逐条写清：
- 页面上会怎么显示
- 用户能做什么
- 系统会怎么响应

## 4. 不在本次范围内

明确这次不做什么，避免范围失控。

## 5. 影响范围

说明本次需求可能影响：
- 哪些页面
- 哪些状态
- 哪些资源
- 哪些提示词
- 哪些存档字段

## 6. 约束与注意事项

说明本次实现必须遵守的特殊约束，例如：
- 不破坏旧存档
- 不新增平台强依赖
- 不修改既有资源结构

## 7. 验收标准

列出完成后如何判断需求达成。

建议写成可验证条目：
- 当……时，应显示……
- 当……操作后，应发生……
- 不应再出现……
