# 实现计划模板

> 文件位置：`docs/plans/YYYY-MM-DD-功能名-plan.md`

## 1. 目标

一句话说明本次实现计划要解决什么问题。

## 2. 涉及模块

列出本次预计会改动的系统/模块/文件范围。

建议说明：
- 主功能域
- 可能受影响的辅助模块
- 是否涉及平台层

## 3. 权威状态来源

明确：
- 本次功能依赖哪些状态
- 哪个字段是权威来源
- 谁负责更新该状态
- 哪些页面会读取该状态

## 4. UI 与交互入口

说明：
- 用户从哪里进入该功能
- 页面上哪些区域会变化
- 是否新增按钮、文案、流程

## 5. 数据与持久化影响

说明：
- 是否影响存档
- 是否新增字段
- 是否需要兼容旧数据
- 是否影响运行时生成资源

## 6. 提示词 / 规则影响

如果需求涉及 AI 推演、提示词、阶段规则，应说明：
- 改哪些提示词或规则
- 是否会影响其他阶段
- 是否需要新增规则文档

## 7. 风险点

列出本次实现的主要风险，例如：
- 状态来源不一致
- 多页面展示不同步
- 存档兼容风险
- 平台能力耦合风险

## 8. 实施步骤

按顺序写出建议实施过程。

示例：
1. 先收敛状态判断
2. 再改页面展示
3. 再补持久化兼容
4. 最后补测试或验收说明

## 9. 验收步骤

说明完成后如何验证。

建议至少覆盖：
- 主路径
- 边界情况
- 存档恢复
- 资源生成或读取

## 10. 后续事项

记录这次不一定立即完成、但后续应继续收敛的问题。
