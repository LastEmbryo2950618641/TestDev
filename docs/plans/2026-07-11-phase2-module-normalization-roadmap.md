# 2026-07-11 Phase 2 Module Normalization Roadmap

## 1. 目标

本阶段路线图服务于以下长期目标：

- 保持玩法逻辑不变
- 继续降低模块耦合与关联性影响风险
- 提高展示层、规则层与动作层的代码复用性
- 为未来 `window exe` 与 `android apk` 复用前端逻辑继续铺路
- 在不触发高副作用链的前提下，持续推进 `publish/` 目录规范化

本路线图不是一次性重构计划，而是后续 2 到 3 个阶段内的低风险推进顺序说明。

## 2. 当前阶段原则

后续推进默认遵循以下原则：

1. 先按已验证模块模式分类，再决定是否改代码。
2. 每次只推进一个低风险切口，不混合玩法改动与结构改动。
3. 优先抽离只读展示 helper、纯规则 helper、纯格式化 helper。
4. 保留旧动作入口或旧根入口作为兼容壳，不追求一次性清空旧文件。
5. 如果开始触碰写回链、持久化链、启动链或宿主差异链，默认停手。

## 3. 下一阶段优先级

### P1. `real-world`

当前定位：

- 已有成熟 `ui/real-world/` 样板
- 已验证“真实 helper 文件 + 聚合入口 + 动作入口保留”模式
- 继续推进能直接增强多端共用展示层

下一步允许的切口：

- 地图信息面板只读摘要 helper
- 室内面板只读标题/标签/列表包装 helper
- 与地图控制信息展示相关的纯格式化 helper

下一步不允许进入：

- canvas 绘制
- runtime cache 管理
- requestAnimationFrame 调度
- 地图点击/拖拽写回
- AI 推演结果落库

多端复用意义：

- `ui/real-world/` 中的 helper 最容易在浏览器、桌面壳、移动壳共用
- 运行时与交互细节继续留在动作层，避免宿主差异扩散

### P2. `settings`

当前定位：

- 已有 `ui/settings` 样板
- 更适合作为“已有 UI 样板继续扩展”的稳定案例

下一步允许的切口：

- 选项说明文本
- provider / model 只读派生列表
- AI 输出限制相关的只读展示 helper
- draw provider / model 的只读可选态总结

下一步不允许进入：

- provider 请求
- 连接测试
- 设置保存
- 远程状态变更

多端复用意义：

- 设置界面的选项展示逻辑未来可直接复用
- 网络请求与平台配置细节继续保留在动作层或未来平台层

### P3. `faction`

当前定位：

- 已形成继续扩展中的 UI helper 样板
- 当前更适合继续从详情页/总览页抽只读 helper

下一步允许的切口：

- 势力详情页的派生文本
- 组织树只读节点包装
- 总览页状态文案与说明文本

下一步不允许进入：

- `initFactionSystem()`
- `syncCompanyFaction()`
- `normalizeFactionStructure()`
- `orgTerritory` / `company` / `membership` 同步链
- `visibleFactions()` 这类跨模块曝光策略

多端复用意义：

- 势力详情和组织树展示规则可以脱离运行时宿主复用
- 跨模块同步链继续留在兼容动作入口，降低连带风险

## 4. 当前阶段不优先推进的模块

### `save`

原因：

- 旧入口后段高耦合
- 继续推进很容易直接进入持久化与恢复链

当前策略：

- 维持停手边界
- 等未来出现更明确切口后再评估

### `loading`

原因：

- 当前风险集中在启动时序与稳定性
- 拆分收益低于黑屏、启动异常等系统级风险

当前策略：

- 仅在具体问题驱动下处理
- 不以目录继续拆分为目标

### `company`

原因：

- 历史上存在编码污染风险
- 中文密集且已有修复痕迹

当前策略：

- 非必要不进入深改
- 只有在有明确纯展示切口且编码安全时再考虑

## 5. 每轮推进的默认动作顺序

每次继续模块规范化前，默认先做：

1. 阅读模块状态图与该模块边界文档
2. 判断当前模块属于哪一种已验证迁移模式
3. 只选择一簇低风险 helper 或一小段纯流程
4. 优先改真实实现文件，再改兼容聚合入口，最后保留动作入口兼容
5. 改动后补边界文档或阶段记录

## 6. 何时必须停手

出现以下任一情况时，默认停止代码推进，先补文档：

- 需要大面积替换中文密集文件
- 继续推进将直接进入写回链、持久化链、启动链
- 需要同时改玩法规则与结构边界
- 只能通过重写大文件才能落地
- 当前收益只是“目录看起来更整齐”而不是复用性提升

## 7. 与多端复用的关系

本路线图默认优先沉淀：

- `ui` 中的只读展示逻辑
- `domain` 中的纯规则与纯格式化逻辑
- `app` 中轻量且与宿主无关的装配逻辑

默认延后：

- 文件存储接入
- 本地数据库接入
- 原生宿主桥接
- 启动时序和高副作用链重组

这样可以保证：

- 浏览器版继续稳定可跑
- 未来桌面壳只需要逐步补平台接入
- 未来移动壳优先复用前端展示与规则层，不从头重写
