# 2026-07-11 High-Risk Legacy File Minimal Edit Strategy

## 1. 目的

本文档用于给后续会话提供一套“高风险旧大文件最小编辑策略”，适用于以下类型文件：

- 中文密集
- 历史上出现过编码污染或恢复痕迹
- 当前 diff 面较大
- 同时承载展示逻辑、写回链、请求链、启动链或宿主差异逻辑

目标不是提高修改速度，而是降低以下风险：

- 为了补一个薄转发，误伤整段旧逻辑
- PowerShell 字符串替换未命中后继续反复试探
- 因为控制台输出异常而误判文件损坏
- 把低风险结构修补演变成高风险旧文件重写

## 2. 典型适用文件

根据当前工作树状态，这套策略优先适用于：

- `publish/settings-actions.js`
- `publish/real-world-map-actions.js`
- `publish/faction-actions.js`
- `publish/worldline-actions.js`
- `publish/save-actions.js`
- `publish/loading-actions.js`
- `publish/company-actions.js`

这些文件并不等价，但共同特点是：

- 当前不适合按“普通小文件”方式反复补丁
- 任何额外编辑都应先说明为什么必须碰它

## 3. 先判断是否真的必须改旧大文件

在动手前，先按顺序判断：

1. 能否先把真实 helper 落到更安全的新文件。
2. 能否只补边界文档或阶段计划，而不改代码。
3. 能否只改聚合入口而不改动作入口。
4. 只有前面都不成立，才进入旧大文件最小编辑。

如果答案仍不清楚，默认停手，不直接改大文件。

## 4. 三种允许的最小编辑方式

### 方式 A：只追加新 helper 文件或新文档

适用：

- 真实 helper 还不存在
- 当前目标是先把只读逻辑从旧文件抽出来

优先级：最高。

原因：

- 这类编辑对旧大文件零侵入
- 最适合作为第一步

### 方式 B：整段替换一个已定位的小区块

适用：

- 目标区块边界非常清楚
- 已经通过读取文件精确看到区块头尾
- 该区块长度可控，且职责单一

例如：

- 某一组连续 helper 转发块
- 某一个已知的只读展示函数簇
- 某一个明显独立的兼容壳片段

执行要求：

- 先读取并保存精确区块文本
- 按整段替换，不做多次模糊字符串替换
- 替换后立刻复查该区块上下文

### 方式 C：单行或少量行的精确定点追加

适用：

- 只是补一个逗号、补一个 return、补一个单独转发方法
- 周围结构稳定，不依赖多层缩进或多种换行混合

执行要求：

- 只允许在定位明确的尾部或相邻行做极小追加
- 一次失败后不应继续多轮试探

## 5. 不推荐的做法

以下方式在高风险旧大文件中默认不推荐：

- 先 `Get-Content -Raw` 再做多轮模糊 `Replace()` 试探
- 依赖控制台输出判断编码是否损坏
- 未确认命中条件就连续做第二次、第三次替换
- 因为“只差几个函数”就把整个尾部整段重写成更大范围
- 顺手把展示逻辑、请求逻辑、保存逻辑一起整理

原因：

- 这类做法最容易让“低风险补缝”演变成“高风险结构扰动”

## 6. 什么时候应该直接停手

出现以下任一情况时，默认停止继续编辑旧大文件：

- 第一次最小替换未命中，且原因不明确
- 文件中已存在编码污染痕迹，且当前补丁需要跨多段中文内容
- 想补的内容只是兼容转发，但当前文件同时承载请求/保存/启动主链
- 继续编辑需要猜测换行、缩进、编码状态
- 本轮收益只是“结构更完整”，但没有强运行时需求

停手后的正确动作：

1. 保留已完成的新 helper / 新文档成果
2. 在计划文档或风险清单中记录缺口
3. 下一轮若要继续，再设计更稳的整段区块替换方案

## 7. 推荐执行顺序

后续如果必须修改这类文件，默认按以下顺序做：

1. 先读风险清单和模块边界文档
2. 先确认真实 helper 是否已存在
3. 先选方式 A / B / C 中风险最低的一种
4. 每轮只尝试一次最小编辑
5. 编辑后立即复查目标区块是否真的命中
6. 如果未命中，不连续试第二种模糊写法，先停手补记录

## 8. 与当前仓库的直接对应

### `settings-actions.js`

当前策略：

- 真实 helper 先落 `publish/ui/settings/view-helpers.js`
- 兼容缺口先记入 `docs/plans/2026-07-11-compat-forwarder-gap-list.md`
- 若未来继续补转发，应优先采用“整段替换 helper 转发区块”的方式，而不是多轮字符串替换

### `real-world-map-actions.js`

当前策略：

- 只继续抽只读展示 helper
- 一旦涉及 cache、绘制、调度链，默认停止
- 如果要补兼容转发，优先用已定位的小区块整段替换

### `faction-actions.js`

当前策略：

- 只继续处理详情页和总览页只读 helper 相关区块
- 不进入初始化与同步主链

## 10. 结论

在当前仓库里，高风险旧大文件的正确处理方式不是“更大胆地改”，而是：

- 更早停手
- 更小区块
- 更少试探
- 更依赖新 helper 文件与边界文档先落地

这套策略的本质，是让结构治理继续推进，但不把推进方式本身变成新的风险来源。
