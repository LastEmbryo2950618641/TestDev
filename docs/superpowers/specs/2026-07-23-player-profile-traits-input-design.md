# 激活表单新增外貌、喜好、性格输入设计

## 目标

在新手机激活资料表单中新增三个可填写的多行字段：外貌、喜好、性格。三个字段同时适用于“创建新账号”和“使用已有账号”流程，并最终进入玩家正式角色卡的 `profile.appearance`、`profile.preferences`、`profile.personality`。

## 方案选择

采用统一表单、按流程同步数据的方案：界面始终编辑 `playerProfile` 中的三个字段；选择已有账号时，同时把修改同步到当前选中的预定义玩家角色卡。相比只修改界面或为两种流程分别维护两套表单，这一方案能保持相同的填写体验，同时确保已有账号最终保存的角色卡不会丢失用户修改。

未采用以下方案：

- 只给新账号增加字段：已有账号仍无法在当前表单直接修改这些资料。
- 新账号与已有账号各建一套输入控件：会产生重复模板和两套校验、同步逻辑。

## 界面

在当前激活资料表单的基础资料区域新增“外貌”“喜好”“性格”三个多行输入框。它们与现有“备注设定”一样允许填写完整描述，不新增弹窗，也不改变激活步骤。

当用户选择已有账号但尚未展开资料区时，仍沿用当前的“展开数值与详情”交互；展开后可看到并编辑这三个字段。选择另一张玩家角色卡时，三个输入框随所选角色卡更新。

## 数据流

### 新账号

1. 输入框读取和修改 `playerProfile.appearance`、`playerProfile.preferences`、`playerProfile.personality`。
2. 激活时，三个字段进入标准化后的基础资料。
3. AI 补全结果不得覆盖用户已填写的三个字段。
4. 生成正式 `player-self` RPG 状态后，三个字段保存在 `state.profile` 中。

### 已有账号

1. 选中预定义玩家角色卡时，将角色卡中的三个字段复制到 `playerProfile`，用于表单显示。
2. 用户修改任一字段时，同时更新 `playerProfile` 和当前选中的预定义玩家角色卡。
3. 确认激活时，现有的预定义角色卡保存流程使用修改后的角色卡创建正式 `player-self` RPG 状态。
4. 最终字段保存在 `state.profile` 中，身份证继续从正式角色状态读取。

空字符串是有效的用户选择，不使用预定义值或 AI 结果回填用户主动清空的字段。

## 边界与错误处理

- 三个字段均为可选项，不阻止激活。
- 对输入进行首尾空白清理和合理长度限制，避免异常长文本进入角色卡。
- 不改变姓名、生日、当前位置和关系角色卡的现有逻辑。
- 不把 RPG 状态中的同名或近似字段作为回退数据源。

## 测试

- 验证激活页面存在三个独立输入框，并绑定正确字段。
- 验证新账号标准化和 AI 补全后保留用户填写值。
- 验证已有账号选择角色卡后，三个字段正确显示。
- 验证已有账号修改字段时，`playerProfile` 与所选角色卡同步。
- 验证保存后的正式玩家角色状态包含三个字段。
