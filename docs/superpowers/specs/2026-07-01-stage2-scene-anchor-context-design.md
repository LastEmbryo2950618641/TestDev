# Stage2 场景锚定上下文瘦身设计

## 目标

Stage2 只负责锚定当前场景，不承担正文续写、final 更新、Stage1 查询规划或 Stage4 结算职责。

Stage2 需要回答：

- 当前行动发生在哪里；
- 当前空间边界是什么；
- 谁必须在场，谁只是候选，谁禁止出场；
- 随机场外事件是否只能保持场外；
- 当前行动可能影响哪些对象或系统事实；
- Stage3 正文应围绕哪些已锚定事实写作。

Stage2 prompt 不得再包含与当前场景边界无关的角色卡全文、玩家完整资料、RPG 数值、财富、性经历、final 规则、Stage1 查询残留或 Stage4 结算合同。

## 当前问题

当前 `buildConfiguredSceneAnchorPrompt()` 直接注入：

```text
compactUpdatePromptText(base, 1600)
sceneLayerSummary(trace)
compactUpdatePromptText(loadedText + materialText, 2200)
```

其中 `base`、`loadedText` 和资料摘要可能混入大量非锚定信息：

- final 阶段规则；
- 桌面时间推进规则；
- 生日、完整地址、财富、父母死因、世界观空字段；
- 玩家 RPG 属性与完整穿着槽位；
- 角色卡全文，包括情绪、感觉、物品、技能、身体状态、性经验次数；
- 势力资料库中的空记录；
- Stage3 正文续写规则；
- Stage1 查询规划字段；
- Stage4 结算/更新判断说明。

这些信息会污染场景锚定，导致 Stage2 把无关设定当成正文或结算依据。

## 设计方案

采用 Stage2 专用瘦身输入路径。

新增 Stage2 锚定上下文构造：

```js
buildSceneAnchorContext({ store, action, base, loaded, trace, materialSession, config })
```

该方法只产出与当前场景锚定直接相关的信息：

```text
模式：现实 / 操控剧情
本次行动：...
当前场景位置：...
当前时间提示：...
空间边界线索：...
参与者边界：...
随机场外事件边界：...
已加载锚定事实：...
```

Stage2 prompt 使用该专用上下文，不再直接渲染完整 `base` 或完整 `loadedText`。

## Stage2 保留信息

### 当前场景位置

保留粗粒度、可用于判断行动发生地的地点信息，例如：

```text
刘家
刘思琪房间门口
卧室门口
走廊
客厅
```

不保留门牌号级完整住址。

### 空间边界

保留会影响入场、听见、看见、触达的信息：

- 门是否开着；
- 是否在门口、房间内、走廊、相邻房间；
- 相邻房间是否可能听见；
- 谁能自然靠近、路过、进入；
- 当前行动是否影响门内、门外、走廊或通信系统。

### 参与者边界

保留：

- 强制出场；
- 高优先候选；
- 戏剧候选；
- 禁止出场；
- 随机场外候选；
- 随机事件闯入条件。

不再保留 Stage1 的 `地点查询`、`因果查询`、`冲突查询` 字段。

### 已加载锚定事实

从已加载资料中只保留和当前场景有关的短事实：

- 角色姓名、身份、与当前位置的关系；
- 角色是否可能自然在场；
- 角色当前已知位置或行动状态；
- 地点空间结构；
- 近期直接影响当前场景的世界线事实；
- 通信或系统事件是否只在场外发生。

## Stage2 删除信息

Stage2 prompt 和 Stage2 上下文不得包含以下内容。

### Final 阶段规则

删除：

```text
时间规则：所有现实时间都以桌面时间为准；本次 final 必须返回 elapsedSeconds，代码会用它推进桌面时间。
elapsedSeconds
final.wechatActions
```

原因：这是 final / 更新阶段规则，不是场景锚定规则。

### 玩家资料中的无关字段

删除：

- 生日；
- 门牌号级具体地址；
- 势力地位：未填写；
- 财富等级；
- 当前财富；
- 财富来源；
- 固定收入；
- 性经验次数；
- 父母去世原因；
- 世界观补全：暂无；
- 强引导备注，例如“三人除姓名和独立人格外……”；
- 玩家属性中的等级、经验、力量、敏捷、体质、智力、感知、意志、魅力；
- 玩家完整穿着槽位。

原因：这些不用于判断当前场景地点、空间状态或出场边界。

### 空资料库

删除：

```text
势力资料库：中华人民共和国 / 公司 / 刘家｜资料库：暂无记录
```

原因：无记录内容没有锚定价值。

### Stage3 正文规则

删除：

```text
需严格跟着世界线续写，保证正文对最新世界线连续性
正文必须服从...
```

原因：这是 Stage3 正文职责，不属于 Stage2 输入。

### Stage1 查询规划残留

删除参与者分层与查询规划中的：

- 地点查询；
- 因果查询；
- 冲突查询。

原因：这些是 Stage1 查询规划，不是 Stage2 锚定任务。

### 角色卡全文字段

从已加载资料摘要中删除：

- 全部情绪值；
- 全部对玩家感觉值；
- 全部穿着槽；
- 全部物品；
- 全部技能；
- 全部核心属性数值；
- 全部身体状态细项；
- 性经验次数或性经验分类细节。

原因：这些属于角色卡全文或结算依据，不是锚定当前场景边界所必需的信息。

### Stage4 结算说明

删除所有结算味过重的扩展说明，例如：

- 结算对象；
- 类型完成；
- 更新类型；
- 情绪/穿着/身体状态结算判断；
- Stage4 才关心的更新边界展开。

原因：Stage2 只输出当前场景影响范围，不执行结算。

## 字段调整

将 Stage2 输出字段：

```text
结算边界：
```

改为：

```text
当前场景影响对象：
```

语义：当前行动在本场景中实际可能影响的对象、地点或系统事实。

该字段只为 Stage3/Stage4 提供边界线索，不在 Stage2 中展开结算规则。

新的固定输出顺序：

```text
场景锚定报告：
当前地点：
当前时间：
空间状态：
当前动作：
强制出场：
高优先候选：
戏剧候选：
禁止出场：
随机事件影响：
正文写作重点：
当前场景影响对象：
```

## Stage2 模板规则调整

当前规则中污染性较强的句子：

```text
正文必须服从本报告。
加载角色卡只作为准确性参考，不等于入场或结算。
禁止出场角色不得出场、不得主动联系、不得结算。
结算边界必须只包含...
```

改为中性的锚定规则：

```text
本报告只判断当前场景边界，不写正文，不写结算。
角色资料只用于判断是否具备当前场景关联，不代表该角色实际在场。
禁止出场角色在当前场景中视为不在场。
随机主动事件默认保持场外；只有存在明确自然闯入条件时，才可写入影响说明。
```

## 数据流

当前数据流：

```text
base
+ sceneLayerSummary(trace)
+ full loadedText
+ materialText
  -> stage2-scene-anchor.md
```

目标数据流：

```text
buildSceneAnchorContext()
+ sceneParticipantBoundary()
+ loadedAnchorSummary()
+ randomEventBoundary()
  -> stage2-scene-anchor.md
```

Stage3 和 Stage4 可以读取 Stage2 的 `当前场景影响对象`，但 Stage2 本身不展开结算协议。

## 组件边界

### `real-world-agent-loop.js`

负责：

- 在 `buildConfiguredSceneAnchorPrompt()` 中使用 Stage2 专用上下文；
- 调整 `sceneAnchorFields()`；
- 调整 `parseSceneAnchorReport()` 输出字段名；
- 保持旧字段兼容时，可在内部同时映射 `settlementBoundary` 到 `当前场景影响对象` 的值，避免调用方立即破坏。

### `real-world-agent-context.js` / `story-agent-context.js`

负责：

- 提供场景锚定专用摘要；
- 从玩家资料、角色卡和资料库中筛掉无关字段；
- 现实与操控剧情共用“只保留当前场景边界信息”的原则。

### `stage2-scene-anchor.md`

负责：

- 只描述场景锚定任务；
- 不包含 final、正文续写、结算或 Skill 执行规则；
- 固定输出 `当前场景影响对象`，不再输出 `结算边界`。

## 错误处理

Stage2 解析仍要求关键锚定字段存在：

- 当前地点；
- 当前时间；
- 空间状态；
- 当前动作；
- 正文写作重点；
- 当前场景影响对象。

如果模型仍输出旧字段 `结算边界`，解析器可以兼容读取并映射为 `当前场景影响对象`，但 retry prompt 应要求使用新字段名。

## 测试计划

新增或更新测试：

1. Stage2 prompt 不包含 final、结算、Stage1 查询残留、角色卡全文字段。
2. Stage2 prompt 包含当前场景位置、空间边界、参与者边界、随机事件边界。
3. Stage2 固定输出字段使用 `当前场景影响对象`。
4. `parseSceneAnchorReport()` 可解析新字段。
5. `parseSceneAnchorReport()` 对旧字段 `结算边界` 做兼容映射，但生成 prompt 不再要求旧字段。
6. 已加载资料摘要只保留锚定事实，不携带完整情绪、感觉、穿着、物品、技能、核心属性、身体状态细项。

## 非目标

本设计不修复 Stage4 滑动窗口重复问题。

本设计不改变 Stage3 正文生成质量策略。

本设计不改变资料库原始存储，只改变 Stage2 prompt 前的摘要筛选。

本设计不删除角色卡字段或玩家资料字段，只禁止它们直接污染 Stage2 场景锚定 prompt。

## 自审结果

- Placeholder scan：无 TBD、TODO 或未定义目标。
- Internal consistency：Stage2 只做场景锚定，字段、数据流和删除清单一致。
- Scope check：范围聚焦于 Stage2 prompt 输入瘦身与字段去结算化，可单独实施。
- Ambiguity check：明确列出保留、删除、字段调整、兼容策略和成功标准。
