# 上下文合理推演提示词策略设计

## 背景

部分生成型提示词使用“禁止编造未出现的组织或角色”等表述。其原意是禁止生成与当前世界观、人物背景或已知事实矛盾的内容，但模型可能将其理解为：只要输入没有逐字提供完整名称，就必须留空。

证书与称号功能暴露了这一问题。玩家资料明确写有“计算机科学与技术硕士”，角色卡提示词也规定学历学位归入 `certificates`，但证书结构要求 `orgName`，同时提示词又禁止编造未出现的组织。模型可能因此返回空数组，而当前完整性校验允许空数组通过。

## 目标

1. 生成型提示词允许并要求依据上下文、世界观、时代、地区、人物经历和通用常识作保守、连贯的合理推演。
2. “禁止编造”统一解释为：禁止与设定矛盾、缺乏逻辑依据、无关扩张或批量生成无关实体。
3. 已经存在明确资格或社会认可证据时，不允许因为具体组织名、部门或细节没有逐字给出而丢弃事实。
4. 历史原文、已发生事件和状态变化等事实读取型提示词继续保持严格证据边界。
5. 证书与称号继续只保存在角色卡 `profile`，不进入 RPG `values`。

## 提示词分类

### 生成型提示词

角色卡、身份补全、组织生成、势力背景和地图构建等提示词负责把已有资料补全为可用世界状态。这类提示词应遵循：

- 明确事实优先，不能修改或否定输入已经确定的内容。
- 缺少次要细节时，根据世界规则和上下文作最小充分推演。
- 推演结果必须与时代、地区、人物年龄、职业、教育背景和组织层级一致。
- 不得为了丰富内容批量增加无关组织、角色、地点或经历。
- 不得生成与背景设定冲突的实体或关系。
- 合理推演得到的细节应在 `reason` 中说明推演依据，不伪装成输入逐字提供的事实。

### 事实读取型提示词

历史查询、微信原文、承诺、图片记录、已经发生的剧情事件和结算变化只能读取或归纳已有证据：

- 没有记录时不得伪造已经发生的事实。
- 允许根据角色性格组织表达方式，但不能创造不存在的历史内容。
- 状态更新必须由正文、用户输入或已经落库的资料支持。

此类提示词中的“禁止编造”不改为自由推演。

## 证书与称号规则

### 证书

学历学位、执照、资质、等级考试、职业资格、驾驶证，以及世界观中的魔法、武道或异能认证都属于 `certificates`。

当输入明确出现上述资格事实时，`certificates` 不得为空。每项包含：

- `orgName`：认证或授予主体。
- `field`：认证领域。
- `level`：资格、学位或认证等级。
- `reason`：事实来源及合理推演依据。

若输入没有逐字给出认证组织，可按时代、地区、教育体系、行业规则和人物背景推演符合设定的主体。能合理确定具体组织时使用具体名称；只能确定组织类型时使用保守且可理解的组织描述。不得因为缺少逐字组织名而丢弃已经明确存在的资格。

例如，“计算机科学与技术硕士”必须形成一项证书；它不应被归入称号或社群角色。

### 称号

公众、行业圈、族群、国家群众、门派或其他社会群体对人物功绩、名望或代表性身份的稳定认可属于 `titles`。

只有输入或上下文存在稳定社会认可证据时才要求非空。普通职位、学历和自我描述不能自动变成称号。

## 完整性校验

角色卡 Part1 校验增加证据感知规则：

1. 没有资格或称号证据时，`certificates`、`titles` 可以为空数组。
2. 角色基础资料、玩家身份区、预设资料或关系上下文出现明确资格证据时，空 `certificates` 判为不完整。
3. 出现明确稳定社会称号证据时，空 `titles` 判为不完整。
4. 不完整字段进入现有缺失字段补全流程，由 AI 根据原始上下文生成；代码不硬编码具体学校、认证组织或称号。
5. 归一化与去重继续使用现有字段结构和唯一键。

## 提示词审计范围

本次修改覆盖：

- 角色卡 Part1 中身份、社群角色、人事归属、证书和称号规则。
- 人事归属更新提示词中“禁止编造未出现的组织或职位”的歧义表述。
- 势力、组织、地图等生成型提示词中会阻止合理背景推演的同类表述。

以下内容保持严格证据边界：

- 微信历史原文、承诺、图片和过去事件。
- 记忆查询返回的已发生事实。
- 正文后状态变化和结算更新。
- 不能仅凭背景推演成“已经发生”的具体事件。

## 数据流

1. 玩家或角色资料进入角色卡生成上下文。
2. 生成型提示词依据明确事实与世界背景补全 Part1。
3. 证据感知校验检查资格与称号证据是否得到对应数组承接。
4. 若遗漏，进入现有缺失字段补全流程。
5. `mergeGeneratedParts()` 与 `validate()` 保留并归一化生成值。
6. 身份页直接读取 `profile.certificates` 与 `profile.titles`。

## 测试

1. “计算机科学与技术硕士”且初次返回空证书时，校验应将 `certificates` 判为缺失。
2. 补全结果生成结构完整的硕士证书，并保留到最终 `profile`。
3. 没有资格证据的普通人物允许 `certificates: []`。
4. 没有社会认可证据时允许 `titles: []`。
5. 硕士不会进入 `titles` 或社群角色。
6. 事实读取型提示词仍明确禁止生成不存在的历史事件。
7. Markdown 提示词生成的运行时 JavaScript 与 Android 镜像保持一致。

## 非目标

- 不由代码硬编码刘悠的具体毕业学校。
- 不把所有职业、学历或关系自动转换成称号。
- 不放宽历史记录和结算变化的事实证据要求。
- 不修改证书与称号的 profile-only 数据边界。
